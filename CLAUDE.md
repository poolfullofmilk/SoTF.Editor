# SoTF Editor

A savegame editor for Sons of the Forest. A WPF window hosts a `BlazorWebView` whose whole UI is MudBlazor, laid out like `WiFiWatch`. It reads a savegame folder, lets people edit it page by page, and writes back only what changed, after a verified copy of the whole savegame.

| Project | Holds |
|---|---|
| `SoTF.Editor.Data` (`net10.0`) | Savegame and game data models, view models, enums, helpers (`AppInfo`, `SaveJson`, `Formatter`, `LoadedValues`, `Constants`, coordinates), and `Resources`: the resx text, `TextKeys`, `GameNames.resx`, the embedded `GameData.json`, `Pois.json`, `ItemPois.json` and `ActorTemplate.txt` |
| `SoTF.Editor.Services` (`net10.0`) | `Savegames` (finding, loading, saving, backups, `PlayerEntries`, `MainViewModel`), `Pages` (one view model per page, `ProgressReader`), `Actors` (`ActorModifier`, `FollowerModifier`, `JsonModifier`), `Map` (`PoiLoader` builds every point, static and from the save), `Tools` (`WorldTools` for the one-click tools, a view model per tool dialog), `Settings`, `Integration` (update check and updater) |
| `SoTF.Editor.Desktop` | `App` (startup, logging, single instance, DI), `MainWindow` (WebView2 host), `Components`, `Theming` (`AppTheme`, `StatColors`), `Interop` (`LocalFiles`, `WindowCaptionTheme`, `Explorer`), `wwwroot` |
| `Tests` | `SaveRoundTrip.cs`, a file-based app, and `Sample`, the savegame it edits |

Packages: MudBlazor, `Microsoft.AspNetCore.Components.WebView.Wpf`, Newtonsoft.Json, NLog. No MVVM toolkit, no Bootstrap, no tray: the editor has no background work, so closing it exits.

## Build, Run And Publish

```bash
dotnet build SoTF.Editor.slnx
```

```bash
dotnet run --project SoTF.Editor.Desktop
```

```bash
dotnet run Tests/SaveRoundTrip.cs
```

```bash
dotnet publish SoTF.Editor.Desktop -c Release
```

The publish folder holds only `SoTF.Editor_v<Version>.exe`: `IncludeAllContentForSelfExtract` and the `BundleWebRoot` and `RemoveLooseWebRoot` targets pack `wwwroot` inside it. The exe is ReadyToRun (`PublishReadyToRun`): 102 MB instead of 79, and the first page opens 100 to 500 ms sooner. The bundle unpacks once, so the size costs nothing after the first start.

`.github/workflows/build.yml` builds in Release and runs `Tests/SaveRoundTrip.cs` on `windows-latest` for every push and pull request; only a tag releases.

### Releasing

Versions take a third number, the owner's pick, which beats the shared one digit rule: every release bumps the patch (`3.9.1`, then `3.9.2`), features included. The minor or major moves only when the owner asks (a 4.0 made on my own was taken back once). The update check, exe name and tag all handle three parts.

The workflow releases, not a hand: `.github/workflows/release.yml` runs the round trip, publishes on a `v*` tag and creates `SoTF Editor v<Version>` with the exe as its only file. Its body lists the commit titles since the previous tag (`fetch-depth: 0`, `git describe` on `<tag>^`), and the update dialog shows them, so commit titles are what users read: they never say Release or a version number. It cannot delete the previous release: the Tag Protector ruleset lets only admins delete a tag, and the workflow token got HTTP 422 (`Cannot delete this tag`) in the 4.2.5 run.

1. `git pull`, the owner edits the README on GitHub.
2. Bump `<Version>` in `SoTF.Editor.Desktop.csproj` first, so the Debug build shows no update dialog. Retake all eleven screenshots from a copy of a real savegame (hash the real `Saves` before and after), copied with `cp -rp` and `touch -r` on the folders so the card keeps its save time, into a generic folder such as `C:\Saves` that the Debug settings point at, because cards show their folder and a scratchpad or profile path names the owner. Check no text or attribute names the owner before each shot. The Debug backups of that save fill the Restore Backup shot. Shots: `Overview.png` (Player), `Inventory.png`, `Storage.png` (Arrow Holder #1), `Followers.png`, `Game.png` (setup), `Npcs.png` (Baby), `Structures.png`, `Map.png`, `Tools.png`, `Backups.png` (Restore Backup, a row picked), `Progress.png` (Collectibles). Over CDP, `Emulation.setDeviceMetricsOverride` at `1600 x 845` and scale `1.6` gives `2560 x 1352`.
3. Update the README, publish, and launch the exe alone from an empty folder (close the installed copy first, it holds the single-instance handle). The README stays short, the owner's pick: no tagline or picture under the title, one plain bullet per feature saying what it does, and every shot in the last section, Screenshots, one column under small titles.
4. Commit, push, `git tag v<Version>`, `git push origin v<Version>`. The tag must match `<Version>`.
5. Once the new release is live, `gh release delete <previous> --yes --cleanup-tag`. Not before: the run needs the previous tag for its notes.

## Where Data Lives

| What | Where |
|---|---|
| Settings (`UserSettings`) | `%AppData%\SoTF.Editor\settings.json` |
| WebView2 profile | `%AppData%\SoTF.Editor\WebView2` |
| Logs | `Documents\SoTF.Editor\Logs` |
| Exports and loadouts | `Documents\SoTF.Editor\Exports`, `Documents\SoTF.Editor\Loadouts` |
| Backups | `Documents\SoTF.Editor\Backups\<steam id>\<SinglePlayer or Multiplayer>\<save id>\<yyyy-MM-dd HH-mm-ss>` |
| Unlocks backups | `Documents\SoTF.Editor\Backups\<steam id>\<file name>\<yyyy-MM-dd HH-mm-ss>` |
| Real savegames | `%UserProfile%\AppData\LocalLow\Endnight\SonsOfTheForest\Saves\<steam id>\<mode>\<save id>` |
| The game's own backups | `<save id>_backup_<yyyyMMddHHmmss>.zip` beside the save folder; the editor ignores them |
| Test sample | `Tests\Sample\76561190000000000\Multiplayer\1000000001`, a real save with a made-up Steam id and no thumbnail |

A Debug build uses `SoTF.Editor Debug` for all of these folders (`AppInfo.FolderName`).

`Multiplayer` saves are games the player hosted. A `MultiplayerClient` save is a game they joined: it holds only their own player, so world pages show a hint and world tools are disabled. The host's save names guests only in `MultiplayerPlayerRolesSaveData.json`, so a host cannot move a friend, but a friend can teleport themselves on their joined save (untested whether the host's game keeps it). A joined save has no `.name` file, thumbnail or host details (two real ones checked), so its card is titled like `Hard 15 Days` (`JoinedGameName`) with a people tile.

## Saving

- **Never edit a real savegame.** Copy it with its parent folders into the scratchpad and point **Savegames → Change** at the copy.
- Every page view model has `Load(Savegame?)` and `Update(Savegame)`. `MainViewModel.SaveChanges` runs every `Update` in a fixed order (setup, state, weather, inventory, armour, followers, player, storage, structures) on a draft (`SavegameStore.Draft`, `SaveDataWrapper.Copy`), so the loaded store never holds merged edits: a failed backup or write leaves it as it was, Revert Page still goes back to the load, and Save retries. A draft without a real difference says No Changes with no backup; otherwise the files are checked (`BackUpLoaded`), backed up and written. Structures find their rows in the draft by index before any removal (`StructuresPageViewModel.Update`), and the Item Plater plates a draft too. Nothing saves while `HasUnsavedChanges` is false.
- `SavegameStore` writes only modified wrappers, all through `FileTransaction.Commit`: every new file is staged under a name only that commit owns (`<file>.<guid>.staged`), the old files step aside (`.replaced`), then the new ones move in. A failure at any step moves every old file back, so loose files and `SaveData.zip` change together or not at all; a failed undo keeps the `.replaced` files and says so. A target gone at write time, or an archive entry gone since loading, fails instead of being skipped or added. Modified flags clear only after the commit. A crash mid commit can still leave a mixed save; the backup taken before restores it, and owned leftovers are never deleted on start. Settings and the player profile use the same commit (`FileTransaction.Replace`).
- `BackupManager.Create` copies every file and compares each byte for byte; a failed copy deletes its dated folder (`NewBackup`), so it never shows up to restore.
- Save asks before overwriting outside changes (`SavegameStore.HasChanged`: every file's name, size and write time against the load, since a file rewritten in place leaves the folder time alone; a vanished folder counts too, and the save then fails cleanly) and warns that saving can undo the game's progress. A Savegames card opens a fresh `Savegame` (`Home.Open`), or the stamp is old and the warning fires for nothing.
- A save with no edits says **No Changes** and writes nothing. A rewrite on a no-op save is a bug, and the round trip fails on it.
- `SaveDataWrapper` keeps each nested document as loaded text, parsed only when a change check, `LoadedCopy` or `Revert` needs it (cloning the world at load cost 90 to 150 ms per open), and counts a marked document only when it differs (`JToken.DeepEquals`). An undone edit or a tool that finds nothing writes nothing, and the close prompt only asks about real changes.
- The player's `_entries` are read through `PlayerEntries` (`Of`, `ByName`): the game can repeat a name, and the newest wins everywhere (summary, Progress, Copy Player, Consumed Items, pages).
- Restore lists the backup's files first, so a missing or empty backup fails before anything is touched, copies the current files to a safety backup, then commits every backup file plus the removal of every save file the backup lacks, nested ones included (the game renames the `.name` file on every save; linked folders are skipped), through `FileTransaction`, so a failed copy or move puts every old file back. Files named `SoTF.Editor.*` are the editor's own: never copied back, skipped by comparisons. Restore prunes only after copying and spares the chosen backup and its safety copy.
- **Backups → Restore Backup** (disabled while `BackupManager.Count` is 0) lists backups newest first as a timeline (`BackupManager.List`); clicking the pick again unpicks it. A two-button switch under it shows one list at a time, starting on the saved one when the backup has it (stacked, the second went unseen): Saved After This Backup is the Save dialog's list, written into the backup as `SoTF.Editor.Changes.json` (`ChangesOf`; the Plater and a restore write their own line, `RestoreKey`, so a safety backup never reads Not Recorded); Differs From Now is `BackupDiff.Describe` on the thread pool, which finds files that differ by SHA-256 (`DifferingFiles`), compares each document a page shows entry by entry, names changes the way that page does, and lists the rest under Other Files; a damaged file (`JsonException` too) reads Unable to Compare and still restores. Both read from the backup to now, so a piece added since is a plus in both (`BackupDiff.KindOf`). Structures and storages match by type and position, so one removed in the middle does not mark the rest. Restore is disabled while the backup equals the save (`BackupManager.Compare`). A card's Restore Backup opens the dialog even when its savegame fails to load, so a damaged save can still be restored and then opens (`MainLayout.RestoreFromCardAsync`), and the dialog warns in amber while the game runs (`GameRunningRestoreWarning`).
- **Delete Backups** switches the list to picking: the newest is locked, so the last save can always be undone, All But Newest skips pinned ones, and Delete N asks and deletes through the guarded `BackupManager.Delete` (only a dated folder inside the backups folder); a folder that fails is skipped and reported.
- Backups are capped at `BackupManager.SizeLimit` (500 MB, no picker). `Prune` deletes the oldest after each new backup but keeps every savegame's first backup, the new one and every pinned one (`SoTF.Editor.Label.txt` holds the label, `BackupManager.Pin`; typing a label pins). `Pruned` raises a warning snackbar, and pruning never fails a save or restore (`TryPrune` logs, an unreadable folder included). Same second backups are `(2)`, `(3)` and on, ordered by that number (`CopyNumberOf`), so newest and oldest stay right past nine. `ChangesOf` drops null lists and entries.
- **Revert Page** (the `Undo` icon inside a page's menu button, `nav-action`, shown while it has edits) shows that page's changes in `SaveChangesDialog` with `Revert`, then takes the page back. Player, Inventory, Storage, Game and Structures keep edits in memory, so `MainViewModel.RevertPage` reloads them. Followers, NPCs, Map and Tools change the JSON at once, so they put back their part from the copy `SaveDataWrapper` kept (`LoadedCopy`, `Revert`): `JsonModifier.RestoreEntries` restores the entries a page owns by unique id and keeps every other entry as the same token. Followers own the follower actors, their memories, items, kill stats and death flags; NPCs every other actor with its memory, items and the spawners; Map the zipline document and the zipline structures (id 55) by position; Tools the documents only tools touch, plus the cannibal memories, kill stats and world counts or the Game State values only after Cannibal Anger or a Game State tool ran.
- Save first shows `SaveChangesDialog`: each page with a menu dot, its icon and up to six change lines (`ChangesOf`, from each page's `ChangedNames` or `Changes`), then an And N More link to `ChangesDialog`, the same as Restore Backup through the shared `ChangeList`. A line leads with its mark: green plus added, amber dot changed, red minus removed (`Change`, `ChangeKind`); a repeat reads once with its count greyed on the right. A page name links to the page and an Undo button reverts it at once (`ChangeList.Actions`, off in the Revert dialog). Save is disabled while nothing is unsaved; with no dot but a changed store it saves straight away and the store decides.
- A savegame that fails to load closes itself (`MainViewModel.SelectSavegame`), so no caller leaves a half loaded page. Open, reload and restore fail through `MainLayout.TryBusyAsync`: logged, with a snackbar offering **Open Backup Folder**, since the closed savegame disables Backups. Busy work runs through `RunBusyAsync`, which yields once so the overlay paints first.
- Closing with unsaved edits asks (Close Without Saving: the question, then Yes, then No, on three lines); Windows shutdown never waits. `YesNoDialog` keeps line breaks (`pre-line`). `MainViewModel.HasUnsavedChanges` asks every page and the store and never merges: a merge for asking wrote edits into the open copy, and a declined discard then saved them.
- Every actor change goes through `MainViewModel.ModifyActors`: unsaved follower edits are written first, then followers and NPCs reload. Removing actors goes through `JsonModifier.RemoveByUniqueId`, which drops every match (the game can repeat a memory) from spawners, influence memories and `NpcItemInstances.ActorItems`, for NPCs and follower copies alike. The actor dialog edits copies of the influences, so closing without Apply changes nothing.
- A new follower (Spawn, or Revive) arrives at `MainViewModel.ArrivalPosition`: the player, or while the player is underground a living follower on the surface, since followers cannot follow into caves. Move to Player, Spawn and Bring to Player stay clickable when a cave blocks them and say why (`FollowersStayOutside`, `NoArrival`), so a greyed button never leaves people guessing. A map teleport of Kelvin or Virginia moves every copy, a step apart; Bring to Player on another actor runs `ActorModifier` with `ActorTeleport.NpcToPlayer`.
- The game deletes a dead follower's actor some time after death and keeps only `IsVirginiaDead` or `IsRobbyDead` (the game calls Kelvin Robby). The panel then shows Dead with no Unique ID, and Revive creates the follower anew (`FollowerModifier.Revive`).
- The game leaves out values that are `0` or `false`, so a missing field reads as its default. Game State and Weather list every known field even when missing (`Constants.GameStateKeys`), and `GenericSetting.MergeTo` adds one only for a non-default value; the Player page does the same for stats, strength, position and area (`PlayerPageViewModel.AddMissingEntries`, `TargetHealth` with `CurrentHealth`).
- The player's cave or bunker is `player.areaMask` (`IntValue`); followers and NPCs carry a `GraphMask`, written with every move.
- A storage keeps every slot the save holds, even past its definition (stone holders hold two stacks now). A stored item writes its loaded `UniqueItems` back untouched; only a changed count or item builds new ones (`StoredItem.UniqueItemsToSave`). A food module swaps only for another food state (`IsEqualTo` on `CurrentState`), or spoil timers reset on every save.
- `Clothing` holds the outfit plus other worn pieces such as the Rebreather. The outfit picker changes only the first outfit entry, and none means the starting Tactical Jacket (`495`). `PlayerPageViewModel.WornItemIds` feeds the map, so a worn Rebreather counts as owned.
- Tools change only the in-memory JSON and return a snackbar message: the one-click world tools are `WorldTools`, the dialog tools have their own view models (`RegrowTreesViewModel` and the rest). The exceptions say so: the Item Plater saves at once (`MainViewModel.SaveWrappers`, after asking to discard edits and reloading; a failure keeps the dialog open), Unlocks edits the owning account's `PlayerProfile.json` after its own backup (nothing when no toggle changed, a missing setting only when on; a locked or damaged profile reads Unable to Read and is never written), and Copy Player writes another savegame after its backup.
- **Copy Player** (`PlayerCopier`) copies the open player as saved on disk (a fresh `SavegameStore`) into another savegame, a joined one included, with chips for Stats (stat and strength entries in place, a zero the source left out removed there too), Inventory (the document plus blueprint page entries, copied only when both saves have player entries), Armor and Outfit (whole documents, `SaveDataWrapper.Replace`). Position, area and raft stay. A part the other save lacks is skipped. Untested in game.
- **Guest Roles** edits `MultiplayerPlayerRolesSaveData.json` on a hosted save (`WorldTools.ReadGuests`, `SetGuestRoles`): every guest by name with Guest, Trusted, Admin and Banned (`GuestRole` 1, 2, 4, 16). The names come from the game code; the numbers are inferred from a save holding 1, 4 and 16, so Trusted as 2 is untested and an unknown value picks none.
- **Ripen Gardens** sets every growing plot (`GrowTimeSecondsRemaining` above 0, seeded) to -1, the side the game counts as ripe. **Fill 3D Printers** raises every printer under 1,000 ml to exactly 1,000 (`WorldTools.PrinterResin`): the real maximum sits in scene data, but a sled prints at 1,000. Printer files carry an underscore the enum cannot (`Resin3dPrinter_BunkerASaveData.json`, `GetFilename`). Both untested in game. There is no rain catcher tool (no known capacity) and no new-item flag cleanup (the game clears them itself).
- **Cannibal Anger** (`CannibalAngerDialog`) sets 0 to 100%: every living cannibal (`ActorType.IsCannibal`, not `StateDead`) gets a Player influence of that anger and its negative as sentiment, both ways, through `ModifyActors`, adding a memory or influence where missing; Fear and other influences stay. At 0 it also resets kills, kills per day, cut trees and village visits. The dialog starts at the `CannibalMood` average and disables Apply while nothing would change. A raise to 30 survived a game load and save; calming is untested.
- Save and Copy Player warn while `SonsOfTheForest.exe` runs (`SavegameManager.IsGameRunning`, checked when the dialog opens): the game writes over the editor's save unless it sits in its main menu.
- `MainLayout.WatchAsync` runs every 2 s on the thread pool (`Polling.EveryTwoSecondsAsync`, which never dies and logs once per failure streak) and sets `MainViewModel.IsGameRunning`, which shows an amber Game Running chip. When the open savegame's files change on disk (`SavegameStore.Stamps`) and hold for one more tick, it reloads with a snackbar, or with unsaved edits offers Reload in a warning snackbar, each change once. It skips a tick while busy or while a dialog, an open menu or select, or a focused text field is in use (`sotfShell.isInUse`), so half typed text is never lost. The editor's own saves load a new store and never count.
- Big actions ask first with one sentence (`EditorPageBase.ConfirmAsync`): every tool, Fill All Storages, Apply to All of Same Type, Remove All, Set All to Remove, Remove All Copies, Remove Copy and Delete Backup.
- Teleport and spawning edit the save, so they work with the game closed.

## Navigation

- The left menu is a `MudNavMenu` of `MudNavLink`s (`Color.Info`, the open page tonal) in groups split by a divider (`s_pageGroups`): Savegames; Player, Inventory, Progress, Followers; Storage, Structures, NPCs, Map; Game, Tools. The Save dialog uses the same order. On a joined save the world pages are disabled (`PageLink.NeedsWorld`) and a caption under the menu says why, since a disabled control gets no tooltip.
- The app bar holds the title, Language and Help on the left, and the Game Running chip, Backups, Reload and Save on the right, Save at the edge. No savegame name and no close button (the owner's pick): the open savegame is the Savegames card with the Open chip and ring, and opening another replaces it.
- Tools lists a card per tool: icon, title and chip on one row, the description under it. Only exceptions wear a chip: **Saves at Once** in amber, **Host Save Only** greyed for world tools on a joined save. A tool that sets a level shows where it stands at the bottom left (`Tools.ValueOf`, only Cannibal Anger).
- Help holds GitHub, **Check for Updates** and About. A found update keeps a red dot until restart: a `MudBadge` on Help, then `update-dot` on Check for Updates.
- A page with changes shows an amber menu dot (`MainViewModel.HasChanges(route)`) at once: `EditorPageBase` implements `IHandleEvent` and calls `NotifyChanged` after each of its own UI events, so only events re-render the layout, never scrolling. Every editing component inherits it (pages, `FollowerPanel`, `GenericSettingEditor`). Map and Progress set `EditsSavegame` false; zipline edits call `NotifyChanged` from `MapViewModel`.
- Map has a menu dot for a moved, new or removed zipline (`SavegameStore.HasModified(ZipLineManagerSaveData)`).
- Tools get their dots from `MainViewModel.FinishTool`, called after every tool with the `ToolState` from before it: the card gets `card-changed` when unsaved files or game state values moved and real changes remain. Set to Endgame and Reset Containers light Game too. Reset Containers clears the matching World Object States like their clear button: it once removed the rows, which the change check never sees, so the reset was never saved. Tools counts as changed only while a run tool's changes remain (`HasChanges("Tools")` also asks the store and Game State), so a tool put back by hand leaves nothing to save, and Revert Tools puts back only the World Object State rows its tools own (`RevertNamedIntDatas`), keeping other Game edits. A tool that moved anything bumps `MainViewModel.Revision`, so the map builds its points again.

## Change Dots

A small amber dot marks every value that differs from what was loaded from disk, and saving clears them all.

- Each page view model remembers its loaded values and answers `IsChanged(...)` and `HasChanges`. Named values go through `LoadedValues`, which compares their text (`Format`: floats invariant, items and outfits by id, positions with their area); list entries that keep their object (armour pieces, inventory items, storages) are keyed by reference; structures need no memory.
- A dot sits on the field that changed, never on a picture or title. A card holding one setting wears it in its top right corner 6 px in (`ChangedDot CardCorner`; only tool cards keep the `card-changed` pseudo dot), so a dot never floats beside a label. `ChangedBadge` puts it on an input's top right corner 3 px in (`changed-host`, `corner`), `ChangedDot` after a text, top aligned. Every dot is 9 px. `StatSlider`, `GenericSettingEditor` and `ItemLabel` take `Changed`.
- A dot is only a mark, never a button (the owner's pick: click to put back shipped in 4.2.3 and is gone). Revert Page takes a page back.
- Where dots go: armour on its Type select for a new piece or type and on durability for a durability change (`IsTypeChanged`, `IsDurabilityChanged`); storage slots on the count; structures on the Modification button, with Percent Done showing the loaded value in green, an arrow and the saved value in amber (`ScrewStructureWrapper.NewPctDone`); NPCs on the name, or the Unique ID while the Name column is gone; influences on each Sentiment, Anger and Fear field (`FollowerPageViewModel.IsChanged(follower, influence, property)`); inventory on the count, and a removed item's dot centred where its count was (`ChangedDot Centered`).
- Followers and NPCs reload after every actor change, so they remember values only when the savegame object changes (a load or a save), and an actor change keeps each panel's copy. Revive refreshes the two death flag rows (`RefreshDeathFlags`).
- Game setup switches and selects go through `SetBool` and `SetString` with the default: a missing setting set back to its default is left out again.
- A blueprint page in `PlayerState` changes only for a blueprint added or removed on Inventory, never to match the inventory on every save.
- With no savegame open, `MainViewModel.HasChanges` answers false before asking any page.
- A dot is computed by whoever renders it. `InfluencesEditor` builds its sliders itself, so it takes `ChangedWhen` (influence and property); `FollowerPanel` passes `OnChanged`.
- Storage compares each slot by item, food state and count (`StoragePageViewModel.ValueOf`), since every food state shares one item id.
- Decimal fields show two decimals, so typing back the shown value (`39,35` for `39,3456`) is a real change and keeps its dot.
- The season bar moves the offset the short way from the loaded offset (`SeasonCalendar.OffsetForDay` from `WeatherPageViewModel.LoadedOffset`, never the edited one, or picks round the year added whole years), and the loaded day brings the loaded offset back exactly.
- Tools that touch only world JSON have no field to mark, and removed entries show only in the menu dot and the save summary.
- To check dots, sweep over CDP: per page change every input, select and switch, check its dot and the menu dot appear at once, put it back, check both go. Filters, map layers and tool inputs get none. Count virtualized tables per row. Type number fields with `Input.insertText` and Tab: a value set from script skips the clamp.

## Text

- Editor text is `Resources/SharedResource.resx` (English, neutral) and one `SharedResource.<culture>.resx` per language: `de`, `es`, `fr`, `nl`, `pl`, `pt-BR`, `ru`, `tr`. Every file holds the same keys and placeholders, none empty, or the round trip fails. Everything reads them through `AppText` (`Get`, `Format`); there is no `IStringLocalizer`.
- `AppText.Languages` lists the shipped languages, each named in its own language and sorted by that name. The picker, `AppCulture.Apply` and the Debug key check read it, and an unknown saved language falls back to English (`AppText.DefaultCulture`). A new language is a resx with every key plus a line there. The picker compares full culture names (`AppCulture.Current`, so pt-BR never reads as pt), and the layout sets `<html lang>` on start (`sotfShell.setLanguage`).
- `AppText.Culture` is the one source of the language. The WPF dispatcher keeps the startup thread culture, so setting `CultureInfo` does nothing; every lookup passes `AppText.Culture`.
- One word per idea in every language: savegame is Spielstand, partie, kayıt; backup Backup, copie de secours, yedek; storage Lager, rangement, depo; follower Begleiter, compagnon, yoldaş; structure Bauwerk, construction, yapı; zipline Seilrutsche, tyrolienne, zipline; item Gegenstand, objet, eşya; NPC NPC, PNJ, NPC; host Host, hôte, kurucu. Spanish (tú): partida, respaldo, almacén, acompañante, estructura, tirolina, objeto, NPC, anfitrión. Brazilian Portuguese (você): save, backup, armazenamento, companheiro, estrutura, tirolesa, item, NPC, anfitrião. Polish (ty): zapis, kopia, magazyn, towarzysz, budowla, tyrolka, przedmiot, NPC, host. Russian (вы): сохранение, бэкап, хранилище, спутник, постройка, зиплайн, предмет, NPC, хост. German speaks as du, French as vous, Turkish sentences as siz with bare verbs on buttons, Dutch as je.
- Polish and Russian put a count after a colon (Kopie: {0}), since their plural endings follow the number; Turkish keeps a name placeholder behind a colon (Canlandırıldı: {0}) for its case endings. French puts a no-break space before a colon or a percent sign. Nunito's Cyrillic subset (`Nunito-Cyrillic.woff2`, Google Fonts v32 like the Latin files) covers Russian.
- A label stays on one line at 1600 x 845 in every language; long ones were cut down until they fit (Max. Gesundheit, Akteur-ID, Tout Remplir, Уник. ID). A CDP sweep of every page and tab in every language at 1600 x 845 and 1280 x 680 finds cut titles (`scrollWidth` past `clientWidth`) and wrapped buttons; tabs read as wrapped because they are tall, World Object State names truncate on purpose, and tool card titles wrap at 1280 x 680 in every language.
- Item, creature and structure names stay English in every language (`GameNames.resx`), because the game shows them in English.
- Labels are short Title Case. Longer sentences (hints, info, warnings, snackbars) are sentence case, short, and never end in a symbol; with two sentences only the last goes without a full stop.

The first and last word and a word after a colon keep their capital (Apply To, In Inventory), and so does Sons Of The Forest. Tabs are Title Case too: `.mud-tab` drops MudBlazor's uppercase.
- Influence types read Player, Cannibal NPCs and Creepy NPCs (`InfluenceCannibal`, `InfluenceCreepy`), so a follower's feelings towards NPCs never read as a kind of follower.
- A count sits after its name, greyed (`mud-text-secondary`), on the right where the row has room, never in brackets: list rows, group titles, options, Apply To buttons (Family 12), repeated changes (`Change.Count`). `GroupTitle` draws a group title with its count, bold, sticky and underlined in blue (`group-underline`, the owner's pick: it says where a group starts). `Formatter.JoinParts` leaves out a missing part and its separator (NPC Creep, not Creep · -). A world item clone reads Golf Cart #3, like Arrow Holder #1.
- A short tooltip is Title Case and puts a value after a colon (Set to Max: 65535); a tooltip that explains stays a sentence.
- A field or section that needs explaining gets a tonal blue `InfoIcon` in a tooltip, never a caption or a button, so it has no hover or press. Beside a switch it sits inside the label, so it follows a wrapped line, and `AppShell.js` cancels its click. `Header` and `StatSlider` take `Info`. Keys are the label key plus `Info` (`EnemyHealthInfo`); Game State and Weather rows get theirs from `TextKeys.SettingInfo` for the names in `TextKeys.SettingsWithInfo`.

- Numbers follow the Windows format; sizes are `Formatter.FormatSize` in MB. Every shown date goes through `Formatter`, the owner's pick: `FormatDateTime` writes `29-10-2026 20:22`, `FormatDateTimeWithSeconds` adds seconds where two backups can share a minute. File and folder names keep the sortable `yyyy-MM-dd HH-mm-ss`. ## Updates

`Updater.CheckAsync` reads the `releases/latest` redirect without following it, so it needs no token. It runs on every start (no setting) and from **Help → Check for Updates**; a newer version opens `UpdateDialog` and sets the red dot. What Changed lists every commit title since the installed build: a workflow build carries its commit (`AssemblyMetadata` Commit from `GITHUB_SHA`, `AppInfo.Commit`), and the compare API (`AppInfo.CompareApiUrl`) lists commits from it to the new tag; a build without one shows the release body (`AppInfo.ReleaseApiUrl`), and no notes hide the list.

Update Now asks to discard edits and hides the X and Escape until the download fails or the window closes (`UpdateDialog.SetClosableAsync`), while `MainWindow.IsUpdating` explains a close. `Updater.DownloadAsync` runs on the thread pool with a progress bar (once per percent, or indeterminate without a length) and saves `SoTF.Editor_<tag>.exe` beside the running exe through a `.download` file that must match the asset's SHA-256 `digest` (`ExpectedDigestAsync`); a mismatch or missing digest opens the release page instead. `Updater.Launch` starts it with `--after-update <pid>` and the window closes without asking (`ClosesWithoutAsking`). The new exe runs `Updater.FinishPreviousVersion` before the single-instance check: it waits up to 15 s for the old process and deletes every other `SoTF.Editor_v*.exe` beside it. A protected folder, a Debug build or a renamed exe (`Updater.CanInstall`) opens the release page. Build with `-p:Version=0.9` to see the dialog, with `GITHUB_SHA` set to an older pushed commit for the full list.

## Looks Wrong, Is Not

- `WebResourceRequested` answers only `https://files.local/` (`LocalFiles`), only for `.png` and `.jpg` files that exist and can be read; a thumbnail the game is writing gets a 404. BlazorWebView routes its own requests through the same event, and answering them breaks the page.
- `MainWindow` and WebView2 both use `#202020`, so the window never flashes white.
- `app.manifest` makes the window per monitor DPI aware (`PerMonitorV2`), or Windows stretched it as a bitmap on a monitor scaled differently; the map re-snaps marks when `devicePixelRatio` changes (`watchScaling`).
- WebView2 zoom and pinch zoom are off (`IsZoomControlEnabled`, `IsPinchZoomEnabled`): a touchpad pinch resized the whole app. The map handles the wheel itself.
- The map points are plain `<img>` drawn by JS (`window.sotfMap` in `AppShell.js`), not Blazor. `MapPoints` renders only the zipline lines and the player's cone, and its only parameter is `MapViewModel.PointsVersion`: when it moves, every visible point is sent once (`sotfMap.points`) with its `.map-points` element, and JS creates elements only for loose points and bubbles within half a view each side (`draw`). With every group on that is about 350 marks instead of 3,500 icons; each icon costs 14 to 20 µs of style per change because its inline style rules out Chrome's style cache. The picked point draws again on top in an overlay. The inherited `cursor` of `dragging` once restyled every icon on press and release.
- Points stay between visits while nothing they show changed (the same `Revision`, structure types and owned items, `PoiLoader.OwnedItemIds`); a new savegame releases them (`MapViewModel.ReleaseIfStale`). `PoiLoader` parses `Pois.json` and `ItemPois.json` once. JS blocks native image dragging and ends a drag on `pointercancel`. Leaving the map calls `MapViewModel.Close`, which ends a pick and keeps the points. `Map.Dispose` never calls JS: awaiting JS while the window closes can hang the shutdown.
- Map points carry no drop shadow: a filter on every icon halved the pan frame rate with all points on. Every mark reads `--map-zoom` in its transform, so a zoom restyles the few hundred that exist; panning restyles none, and `--map-zoom` is set only when it changes.
- Every mark lands on whole device pixels: `apply` rounds the pan from the viewport's own offset, and each icon, ring and bubble carries its spot as `--x` and `--y` (`MapPoints.PoiStyle`), from which CSS rounds with `--map-zoom` and `--dpr`. Checked over CDP at 125% and 150%. A hovered or picked icon is scaled, so it is off the grid while it is.
- The map picture is `dark.webp` (1.7 MB at quality 90). Every source is 4096 px, so it cannot get sharper. Creature icons are the game's 32 px cutouts and look softer at 150%; no larger cutout exists. Pictures carry no cache header: BlazorWebView answers with no-store, yet Chromium asks once per page load.
- Item pictures are the 128 px files shown at 32 px (`Item.ImageUrl`); the 32 px `_tn` thumbnails blurred at 125%. Actor types 31, 52 (Eddy) and 100 have no picture, so `Actor.ImageUrl` falls back to the question mark.
- `.mud-tabs-panels` carries a 0.3 s transition that made a tab grow in slowly; `SoTF.Editor.css` turns it off.
- `.mud-table-container` inherits the table's background: at 125% Chrome repaints a transparent scroller every frame, so Inventory and Structures scrolled at 30 fps.
- MudBlazor draws a slider thumb as a 2 px circle scaled six times, lopsided at 125%; the CSS gives it a real 12 px size. Sliders carry no `ValueLabel`: the label already shows the value.
- Snackbars stop at 92% opacity (`MaximumOpacity`, the owner's pick) and fade in 200 ms, out 250 ms; the defaults looked half see-through for seconds.
- The zoom buttons and point panel share the `map-overlay` glass; plain filled buttons vanished over the map. `PoiDetails` calls `OnMapChanged` after closing or removing, because a child's event only re-renders the child.
- `MudSelect` puts `Class` and `Style` on an inner element, so placing one takes a `MudElement` around it. The update badge around Help carries `d-flex`, or `MudBadge` lifted Help 2 px.
- `panel-flush` sets `overflow: hidden`, which beats MudBlazor's `overflow-y-auto`; `.panel-flush.overflow-y-auto` brings scrolling back.
- The savegame card buttons sit in a plain `span` with `@onclick:stopPropagation`, because event modifiers only work on HTML elements.
- Repeated rows hold no popover component. Structures and Storage open one shared `MudMenu` at the cursor (`PositionAtCursor`, `OpenMenuAsync(args)`); Storage's sits in the header, since MudBlazor never places a menu whose anchor scrolled away. Both buttons carry `data-menu-at`: `AppShell.js` sends a keyboard click from below the button, focuses the picked item, walks items with the arrow keys and gives focus back. A select per slot made switching a 12 slot storage 170 ms instead of 80, Structures fired about 1,600 interop calls on open, and a virtualized `MudTable` rebuilds its rows twice on first load, so every per-row popover leaked into the provider with its row and the save JSON.
- `IncludeSourceRevisionInInformationalVersion` stays false, so the product version reads plain; the commit rides in `AssemblyMetadata`. A `v1.0` tag parses as `1.0`, lower than `1.0.0.0`, so it never prompts falsely.
- `SaveDataWrapper.SerializeAllModified` skips a key with no parsed node (`TryGetValue`): a token edited in place is already in its parent.
- `NamedIntDatas` compare as a set: the editor sorts them, the game does not. `GenericModule` compares its token with `JToken.DeepEquals`; a record compared a `JObject` by reference and made every storage look changed.
- Armour pieces keep the slot they were loaded in; only a new or clashing piece takes the next free one (`PlayerArmourSystemModel.ArmorSlots`). Renumbering made every save a change. Default durabilities are the game's since Patch 05 Hotfix 3: Leaf 25, Hide 40, Bone 65, Creepy 80, Tech 100, Solafite 130 (a real save loads Creepy at 80).
- The setup merge writes each known setting as name, type and value only and leaves unknown settings untouched; it drops a known setting back at its default and counts that as a change. Keys come from the game's own list in `global-metadata.dat` (Inventory Pause is `GameSetting.Survival.PausedInInventory`, checked in game). `SleepingDelay` and `InstantSleepSeasonSwitch` exist but their values are unknown, so the page leaves them out.
- One memory per actor: when `InfluenceMemory` repeats an id, the newest entry wins and a repeated type counts once. A new actor never takes an id that still has a memory (`ActorCreator.UniqueIdsOf`): the game once deleted Virginia but kept her memory, Revive reused id 31, and she showed every influence three times.
- Every Kelvin and Virginia, spawned copies included, gets its own `FollowerState`, merged by unique id; spawning selects the newest. `FollowerPageViewModel.HasChanges` remembers the follower ids, so a spawned or removed copy lights the menu. The save holds no creation time for an actor.
- Platforms (98, 99) list no build cost in `GameData.json`, so `ScrewStructure.BuildCost` is null there: unknown, not free. An unfinished one reads Unfinished · N Added, and a structure the editor cannot change keeps On Save greyed with the reason as title (`Structures.LockedReason`).
- Regrow Trees regrows the share asked for, so 30% regrows about 30% of the cut trees.
- The save holds no length per season, only the custom `SeasonLength` for all of them. Season Day Offset (`_startingDayOffset`) shifts where the year stands: tested in game, day 36 at offset 5 showed spring, at 15 autumn. The season is `floor((days + offset) / days per season) mod 4` from Spring (`SeasonCalendar`: Default 5, Long 10, Realistic 90; Short is unknown). `_startingDayOffset` is a `Decimal` setting saved as `5.0` holding a `double`; an `int` made every save a change.
- Max Health is `100 + 2` per Strength Level above 1; a save storing 100 at level 41 showed half health in game. `TargetHealth` is written only when Current Health changed. `PlayerState.CurrentHealth` reads capped by `MaxHealth` but keeps the value set. Moving the player clears `player.localToRaftUniqueId`, or the game puts them back on the raft.
- The log holds events, not lists: no line per World Object State, unchanged storage or nameless joined save.
- The static map points come from `lmachens/sons-of-the-forest-map` (MIT), and much of the save handling started from SOTFEdit by codengine (MIT), both credited in `THIRD-PARTY-NOTICES.txt`; keep it while either ships. The editor itself is GPL-3.0.
